## truck_lane_change — смена полосы при потере CAM

**Основной ВКР-сценарий.** Демонстрирует причинно-следственную цепочку:

```
потеря CAM (низкое SNR / перегрузка) → запоздалое обнаружение лидера → столкновение (low PRR) или объезд (high PRR)
```

### Как работает

В одном прогоне создаётся цепочка из нескольких автомобилей с разными профилями качества канала:

| Автомобиль | Мощность (dBm) | Target PRR | Ожидаемое поведение |
|---|---|---|---|
| `veh3` | 23 | 0.95 | Получает предупреждения, перестраивается безопасно |
| `veh4` | −20 | 0.077 | Теряет пакеты → `DROP_PHY → drop_decision_no_action` → столкновение с `veh2` |
| `veh5` | 0 | 0.693 | Позже перестраивается, обходя место ДТП |

### Запуск

```bash
# Из корня репозитория
experiments/truck_lane_change/scripts/run.sh

# С GUI SUMO
SUMO_GUI=1 experiments/truck_lane_change/scripts/run.sh

# Без Sionna (fallback)
USE_SIONNA=0 experiments/truck_lane_change/scripts/run.sh

# С Sionna (по умолчанию)
USE_SIONNA=1 experiments/truck_lane_change/scripts/run.sh
```

### Артефакты

| Файл | Описание |
|---|---|
| `artifacts/eva-collision.xml` | Факты столкновений в SUMO |
| `artifacts/drop_decision_timeline/*` | ID-aware `pkt_uid: DROP_PHY → DECISION` |
| `artifacts/collision_causality/*` | Causal report `loss → no_action → collision` |
| `artifacts/eva-veh*-PROFILE.csv` | Профиль `dBm/target PRR/drop-prob` по каждому ТС |
| `artifacts/truck_lane_change_story/*` | Дипломные графики |

### Автоматические графики

- `speed_lane_timeseries.png` — скорости/полосы `veh2..veh5`
- `gap_ttc_timeseries.png` — динамика gap/TTC для пар
- `ns3_events_per_second.png` — DROP_PHY, no_action и lane-change
- `event_chain_timeline.png` — сводная шкала событий
- `event_chain.csv` — та же шкала в табличной форме

Результаты по умолчанию: `~/NEWWAY_runs/<дата>/truck_lane_change/`

## intersection_crash — конфликт на перекрёстке

Детерминированный junction-кейс:

- `veh2` (emergency, main stream) проходит priority junction
- `veh3` (minor stream) должен уступить — при низком PRR не уступает → столкновение
- `veh4` (third direction) не теряет пакеты, ждёт и проезжает безопасно после ДТП

### A/B режимы

**Safe (высокий PRR):**
```bash
USE_SIONNA=1 SUMO_GUI=1 \
PHY_ONLY=1 ALLOW_MANUAL_RX_DROP=0 \
VEH3_EQ_DBM=23 VEH3_TARGET_PRR=0.95 \
experiments/intersection_crash/scripts/run.sh
```

**Crash (низкий PRR):**
```bash
USE_SIONNA=1 SUMO_GUI=1 \
PHY_ONLY=1 ALLOW_MANUAL_RX_DROP=0 \
VEH3_EQ_DBM=-30 VEH3_TARGET_PRR=0.02 \
experiments/intersection_crash/scripts/run.sh
```

### Артефакты

- `artifacts/eva-collision.xml` — коллизии (включая junction)
- `artifacts/drop_decision_timeline/*` — `DROP_PHY → DECISION` по `pkt_uid`
- `artifacts/collision_causality/*` — причинная выборка
- `artifacts/intersection_summary.csv` — компактная сводка

## intersection_radar_comm — радар + V2X comm

Три режима для исследования роли локального радара vs V2X коммуникации:

| Режим | Радар | V2X канал | Ожидаемый исход |
|---|---|---|---|
| `radar_bad_link` | ✓ | Деградированный | ДТП |
| `radar_only` | ✓ | Выключен | ДТП |
| `radar_good_link` | ✓ | Штатный | Безопасный проезд |

### Запуск

```bash
# Сначала Sionna server
experiments/intersection_radar_comm/scripts/start_sionna_server.sh

# Все три режима
experiments/intersection_radar_comm/scripts/run.sh

# Или по одному
experiments/intersection_radar_comm/scripts/run_radar_bad_link.sh
experiments/intersection_radar_comm/scripts/run_radar_good_link.sh
```

### Ключевые параметры

| Параметр | Значение по умолчанию |
|---|---|
| `TX_POWER_DBM` | 23 |
| `SENSOR_RANGE_M` | 30 |
| `SENSOR_REACTION_DISTANCE_M` | 14 |
| `CAM_REACTION_DISTANCE_M` | 95 |
| `VEH3_GOOD_EQ_DBM` | 23 |
| `VEH3_BAD_EQ_DBM` | −30 |

## cpm_perception — коллективное восприятие (CPM)

Сравнение трёх режимов для демонстрации пользы cooperative perception:

| Режим | Описание |
|---|---|
| `sensor_only` | Только локальная реакция по сенсору, CPM выключен |
| `sensor_good_cpm` | Локальный сенсор + рабочий CPM канал |
| `sensor_bad_cpm` | Локальный сенсор + деградированный CPM у `veh4` |

```bash
# Все три режима
experiments/cpm_perception/scripts/run.sh

# По одному
MODE=sensor_only experiments/cpm_perception/scripts/run.sh
MODE=sensor_good_cpm experiments/cpm_perception/scripts/run.sh
MODE=sensor_bad_cpm experiments/cpm_perception/scripts/run.sh
```

> ⚠️ Работает **только** через Sionna. Предварительно поднять Sionna server.

## compare_tech — сравнение радиотехнологий

A/B/C сравнение на двух кейсах (`truck`, `intersection`):

- **802.11p** (IEEE WAVE)
- **LTE-V2X** (C-V2X)
- **NR-V2X** (5G)

```bash
# Все технологии, оба кейса
experiments/compare_tech/scripts/run.sh

# Только LTE vs 802.11p
TECHS_CSV=80211p,ltev2x experiments/compare_tech/scripts/run.sh
```

Режим `COMPARE_MODE`:
- `channel` (по умолчанию) — сравнение по каналу/MAC
- `scenario_replay` — воспроизведение "lossy vehicle" логики

## strict_sionna_vkr — строгий Sionna-пакет

Полный набор manifests, сцен и скриптов для **строго воспроизводимых** Sionna-прогонов. Три сценария:

1. **`strict_lane_obstacle`** — остановка emergency ТС, реакция по NR sidelink
2. **`strict_intersection`** — `radar_only`, `radar_bad`, `radar_good`
3. **`strict_onramp_merge`** — merge-конфликт на въезде

### Строгие гарантии

- Все manifests явно задают Mode 2 параметры
- `enableSensing=1` принудительно
- Запрещены legacy shims: `per-vehicle-prr-profile`, `equiv_tx_power_dbm`, `crash-mode` и др.

```bash
# Запуск одного сценария
python3 experiments/strict_sionna_vkr/scripts/run_strict_scenario.py \
  --manifest experiments/strict_sionna_vkr/manifests/strict_intersection/radar_good.json \
  --out-root analysis/strict_runs

# Batch по seeds
python3 experiments/strict_sionna_vkr/scripts/run_strict_batch.py \
  --scenario strict_intersection --out-root analysis/strict_runs --seeds 11,12,13,14,15
```
